# The product problem

Overkill Factory does not exist because agents are useless. It exists because agents are useful enough to become dangerous when they work without a production contract.

The risk is not only that an agent fails. Clear failure is easy to see: the command breaks, the test fails, the file is missing. The expensive problem is an agent that fails while looking productive.

## False progress

False progress is motion without confidence.

The card moves. The agent comments. A file appears. A test passes. A screen opens. A review gets an “LGTM.” But no one proved that the work solves the right request.

Examples:

- a bug “fixed” without a test that failed before the fix;
- a release “ready” without rollback, owner, monitoring, or human decision;
- a screen “done” without error, loading, empty state, mobile, permission, or clean console;
- documentation published without proving that a reader reaches first success;
- a worker saying “done” without artifact readback.

## The operator becomes the factory

Without a factory, the operator becomes PM, QA, auditor, security reviewer, release manager, and detective.

They must remember context, ask for evidence, verify source preservation, decide whether a blocker is theirs, demand review, compare scope, distrust screenshots, and interpret logs. That does not scale.

The Factory exists to remove that invisible work from the operator.

## Kanban without contract is not enough

A board shows motion. Motion is not delivery.

A card in done only matters if there is a rule of done, evidence tied to the request, consumed review, and a receipt. Without that, the board becomes organized theater.

Hermes is necessary because it holds live state. The Factory is necessary because it defines the contract that prevents that state from becoming noise.

## Green tests are not enough

A green test can be excellent. It must prove the right behavior.

A generic test does not prove a bug. A build does not prove a product. A local smoke does not prove live Hermes execution. A screenshot does not prove a journey. Valid JSON does not prove human approval.

The Factory forces the better question: which request does this evidence prove?

## Bad human approval is false safety

“Can I continue?” is not a human gate.

A real human gate shows what is being approved, what is not, which evidence exists, which risk remains, and what happens if the human refuses.

## Why this needs a factory

A better prompt helps, but it is not enough. The problem is production: source, scope, authority, method, worker, evidence, review, blocker, decision, and learning.

The Factory organizes those elements into a production line. It does not promise perfection. It promises the system cannot hide behind confident prose.
