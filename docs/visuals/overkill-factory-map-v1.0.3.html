Mapa público visual · Factory V3 · v3.0.2

Uma fábrica para trabalho de produto feito por agentes.

Em português simples: você traz uma ideia. A fábrica entende, escolhe o caminho seguro, cria trabalho para especialistas, exige prova e só chama de pronto quando Hermes, contratos e evidências concordam.

O que mudou na V3

Não é mais uma esteira reta

O fluxo tem fases, mas a rota pode ramificar: discovery, segurança, Product Face, capability acquisition, repair, human gate ou release. O contrato decide; o agente não inventa o caminho.

Hermes roda o chão de fábrica

Cards, dependências, typed blocks, dispatch, worker execution, comentários e logs ficam no Hermes Kanban.

Overkill Factory define o método

A fábrica cuida de schemas, gates, workers, autoridade, Product SOT, Method Contract, Receipt Five, release checks e learnback.

Done exige prova

Worker packet não é execução. Resultado de agente não é release. Demo não é produto. Done exige evidência específica e Receipt Five.

Como funciona para uma pessoa não técnica

1. Entrada

Você fala com o gerente. Pode ser Telegram, CLI ou outro canal do operador. A fábrica não começa codando.

2. Entendimento

A fábrica separa fonte, suposição e decisão. Se faltar algo importante, ela pergunta antes.

3. Roteamento

O caminho não é mais uma esteira reta. O contrato escolhe trilho, gates, especialistas, dependências e reparos.

4. Execução Hermes

Hermes Kanban é o chão de fábrica: cards, workers, bloqueios, dependências, comentários, logs e estado real.

5. Prova

Nada vira done só porque um agente disse. Precisa evidência, teste, revisão, readback e Receipt Five.

6. Learnback

Quando algo ensina a fábrica, vira proposta revisável. Não muda regra em silêncio.

Mapa simples da produção

Você não precisa decorar isto. A ideia é mostrar que cada etapa tem dono, saída esperada e gate. Se algo falha, a fábrica volta para o reparo certo em vez de pedir aprovação humana à toa.

Regras que importam

Fonte de verdade

Hermes Kanban + resultados dos workers + Receipt Five. Este mapa ajuda a entender; ele não prova runtime e não é fonte de verdade.

Human gate é exceção

O operador só decide quando há risco real: produção, release, fundos, secrets, mainnet, privacidade, autoridade R3/R4 ou mudança de escopo.

Produto visível tem régua própria

Product Experience Plan, Product Face Packet, DESIGN.md, screenshots, UX proof, acessibilidade e performance note.

Solana/onchain

Solana AI Kit é obrigatório para domínio Solana. Mainnet, fundos e signing exigem autoridade explícita.

Primeiro caminho para testar

factoryctl doctor
factoryctl run minimal
factoryctl v3-production-activation-check
factoryctl literal-dod-audit

O audit literal separa suporte local de prova externa. Se Telegram live ainda não foi verificado, ele mostra PARTIAL_EXTERNAL em vez de fingir 100%.

Limite honesto

Este mapa não é runtime evidence, not runtime evidence, not a source of truth. Ele não prova que um produto específico está pronto. Produto pronto precisa de fonte real, execução, evidência, revisão e release readiness próprio.
